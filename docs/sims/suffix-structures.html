Indexing a text: suffix arrays, the BWT and the FM-index

String matchers such as Knuth–Morris–Pratt (KMP) scan the whole text for every query. If the text is fixed and huge (a genome, a code base) we can sort its suffixes once and then answer each query in time that depends on the pattern. Build a suffix array by prefix doubling, its Longest Common Prefix (LCP) array by Kasai's algorithm, the Burrows–Wheeler Transform (BWT), and search it backward with the FM-index.

From this page to a genome aligner

FM-index. Ferragina and Manzini (2000) observed that backward search needs only L, the small table C and a structure answering Occ(c, i), the rank of c in L[0..i−1]. With rank structures over a compressed L, the index takes space close to the compressed size of the text, and counting the occurrences of a pattern of length m costs O(m) rank queries, independent of n. To report positions you also keep a sample of the suffix array (say every 32nd entry) and walk with LF from any row until you reach a sampled one.

In production. Short-read aligners in genomics, such as Bowtie (Langmead et al., 2009) and BWA (Li and Durbin, 2009), index a reference genome of about three billion bases with an FM-index and use backward search to place each read. The bzip2 compressor uses the BWT itself.

Building it at scale. Prefix doubling (Manber and Myers) is easy to see but needs about log₂ n rounds. Production libraries use linear-time induced sorting (SA-IS, Nong, Zhang and Chan, 2009), and the LCP array then follows in linear time by Kasai's method shown in stage (b).

The r-index. A collection of thousands of nearly identical genomes has a BWT made of few, long runs; stage (c) counts them as r. Gagie, Navarro and Prezza (SODA 2018; journal version 2020) showed how to count and locate all occurrences using only O(r) words of space, where r can be far smaller than n. This makes pangenome indexes practical, and is an active research area.

How to read this

  • The top strip is the text T with its positions. Each row below is a suffix (stages a–b) or a rotation (stages c–d); the column i or SA says where it starts in T, and r is its rank in sorted order.
  • (a) The blue tint covers the prefix that the current ranks already account for (1, 2, 4, 8, … characters). A purple bar to the left of the rows joins suffixes that still share a rank. The pair column is (rank[i], rank[i + k]); "−1" means the suffix ended.
  • (b) The blue row is suffix i, the yellow row is the one just above it in sorted order. Purple cells are already known to match (carried over in h); green matched, red is the mismatch that stops the scan.
  • (c) F is the first column, L the last (the BWT). In the inversion, an arrow goes from L[r] to the same character in F; ringed L cells are the earlier copies of that character, which fix its rank.
  • (d) The blue band is the interval [sp, ep] of rows that start with the suffix of P read so far. Yellow L cells are the ones equal to the next pattern character; LF-mapping turns them into the next, narrower band.

Try this

  1. Rounds. In stage (a) with banana$ the order is final after 2 doubling rounds; mississippi$ needs 3. Type aaaaaaaaaaaaaaa: every round only halves the ties, and you need ⌈log₂ 16⌉ = 4 rounds.
  2. The h pointer. In stage (b) with mississippi$, watch the purple cells: when suffix 1 "ississippi$" has LCP 4 with the row above, suffix 2 starts with h = 3 for free. Total character comparisons stay at most 2n = 24.
  3. Runs. In stage (c), compare the run count r for the DNA-like preset (three copies of a word) with a random text of the same length. Repetition makes long runs.
  4. Backward search. In stage (d), search mississippi$ for ssi: the band goes from all 12 rows to 4 rows ('i'), then 2 ('si'), then 2 ('ssi') at positions 2 and 5. Then try ssm: the interval empties after two characters.
  5. Longest repeated substring. The maximum of the LCP array is the longest substring that occurs twice. For banana$ it is "ana" (LCP 3). That is the idea behind the Arena problem below.
