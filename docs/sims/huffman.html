What's happening

How to read this

  • The stage shows the forest inside the priority queue, lightest tree on the left. Rectangles are symbols (leaves) with their frequency; circles are merged trees with their total weight.
  • Each step removes the two lightest trees (yellow) and joins them under a new root (red). The first one removed becomes the left child (edge 0), the second the right child (edge 1).
  • A symbol's codeword is the list of edge labels on the path from the root down to its leaf. Because symbols only live in leaves, no codeword is the prefix of another — decoding never needs separators.
  • Average bits per symbol = Σ frequency × codeword length. Compare it with a fixed-length code, which needs ⌈log₂ n⌉ bits for n symbols.

Try this

  1. Textbook table (A .35, B .1, C .2, D .2, _ .15): expect codewords A 11, B 100, C 00, D 01, _ 101; 2.25 bits per symbol vs 3 fixed, a 25% saving.
  2. Practice instance (A .1, B .1, C .2, D .2, E .4): build it with both tie-breaking rules. Both average 2.2 bits, but the codeword-length variance is 0.16 with “oldest first” and 1.36 with “newest first”. Which would a data link prefer?
  3. Type text with one very common letter (e.g. AAAAAAAABC). How short does that letter's codeword get?
  4. Give all symbols equal weight (e.g. 8 symbols of 0.125). Huffman should reproduce a fixed-length 3-bit code.
  5. Encode DAD_CAB, then animate decoding: at each 1 or 0 the decoder moves right or left; at a leaf it prints the symbol and jumps back to the root.
