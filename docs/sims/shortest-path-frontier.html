Per edge, Dijkstra's binary heap costs a factor that grows like log n — the sorting barrier in action. Dial's buckets cost a constant per edge (plus one step per distance value). Bellman–Ford's cost per edge is its number of rounds, which grows with the number of edges on the shortest paths. The 2025 algorithm brings the per-edge factor down to log2/3 n in theory; it is not plotted, because nobody runs it on graphs this small (see below).

The 2025 algorithm: what this page shows, and what it doesn't

Duan, Mao, Mao, Shu and Yin compute shortest-path distances on directed graphs with real, non-negative weights in O(m log2/3 n) time, deterministically, in the comparison-addition model — faster than Dijkstra's O(m + n log n) on sparse graphs. It won the best paper award at the ACM Symposium on Theory of Computing (STOC) 2025. Dijkstra is stuck near n log n because it hands out vertices in sorted order. The new algorithm never sorts the whole frontier.

Its main routine, Bounded Multi-Source Shortest Path (BMSSP), takes a bound B and a frontier S and finishes every vertex whose distance is below B and whose shortest path goes through S. It is recursive, with about (log n)/t levels where t = ⌊log2/3 n⌋. At each level it first calls FindPivots, the step animated above: k = ⌊log1/3 n⌋ rounds of Bellman–Ford-style relaxation from S, then the pivots, the vertices of S whose tight-edge trees have at least k vertices. Lemma 3.2 of the paper: there are at most |W|/k pivots, and every vertex below B that goes through S is either already complete in W or has a complete pivot on its shortest path. Only the pivots go into a special data structure (Lemma 3.3) that supports inserts, batch-prepends and pulls of the next few smallest items without keeping everything sorted. BMSSP then recurses on those batches with smaller bounds.

BMSSP(level l, bound B, frontier S) // outline, not animated here if l = 0 then BaseCase: a small Dijkstra from the single vertex in S, stopped after k + 1 vertices P, W ← FindPivots(B, S) // ← the step this page animates D ← the partial-sorting structure of Lemma 3.3, filled with the pivots while D is not empty and not too much work has been done do Sᵢ, Bᵢ ← pull a batch of the smallest pivots from D, with a bound Bᵢ Bᵢ′, Uᵢ ← BMSSP(l − 1, Bᵢ, Sᵢ) // recursion finishes everything below Bᵢ′ relax the edges out of Uᵢ; insert or batch-prepend the vertices they improve into D return the bound reached and every vertex finished

What is simplified here: the paper first transforms the graph so every vertex has in- and out-degree at most 2, and assumes all path lengths are distinct (so the tight edges form a forest); this page uses the graph as drawn and breaks ties by the smallest-numbered parent. The frontier S is built the way BMSSP's requirement allows: everything below b is finished and S is what Dijkstra's heap would hold at that moment. The answer key under "Why the frontier shrinks" checks Lemma 3.2 against the true distances on every run.

How to read this

  • Vertices. Grey = not reached yet. Blue = reached, with a tentative distance (shown next to it on small graphs). Green = settled: the algorithm knows the distance is final. Orange = the vertex being processed. The double ring is the source.
  • Edges. Each arrow carries its weight. Orange arrows form the current shortest-path tree (each vertex's best known parent). Yellow arrows are being relaxed right now.
  • The strip under the graph is the algorithm's priority structure: Dijkstra's heap in array order (root first), Dial's circle of C + 1 buckets (each slot labeled with the distance it currently stands for), Δ-stepping's buckets of width Δ, or FindPivots' sets S, W and P.
  • The order chart plots each vertex's distance against the moment it was settled. Dijkstra and Dial draw a staircase that only goes up: they output vertices sorted by distance. Δ-stepping is sorted only bucket by bucket. Bellman–Ford never certifies anything early; the chart shows when each distance became correct.
  • FindPivots colors. Faded green = finished before the call. Blue = the frontier S and what the rounds reach. Yellow = reached in the current round, then the trees of pivots. Purple = pivots. Green = in a small tree: done without any heap. Dark grey = reached, but at distance ≥ B (outside this band).

Try this

  1. See the sorting barrier. Run Dijkstra on the small example and watch the order chart: every new point is at least as high as the last. Switch to Bellman–Ford: the points jump around, because it fixes distances in whatever order the edge list allows — and it needs several full passes to be sure.
  2. Buckets instead of comparisons. Pick Dial on a random graph with n = 120 and seed 7. There are no heap comparisons at all; instead the pointer steps through the buckets. With C = 3 it takes 25 bucket steps, with C = 20 it takes 128: Dial is O(m + n·C), great for small integer weights only.
  3. Turn the Δ dial. Same graph (C = 9), Δ-stepping. With Δ = 1 every bucket is a single distance value: no re-insertions, but 53 phases, one per distance. With Δ = 40 there are only 2 buckets and 20 phases, but 31 re-insertions — vertices get improved again and again inside the big bucket, as in Bellman–Ford. Values in between keep both small; that trade-off is why Δ-stepping is the standard parallel SSSP algorithm.
  4. Watch the frontier shrink. FindPivots mode on that graph with 30% finished and k = 3: Dijkstra's heap would hold |S| = 20 vertices, but only |P| = 2 pivots remain. The "frontier sweep" table repeats the experiment at other moments: |P| is usually a small fraction of |S|, and never more than |W|/k.
  5. Make it grow fast. Set "already finished" to 0% (the top-level call, S = {source}) and k = 4: within a round or two |W| exceeds k·|S| = 4, so FindPivots stops early and returns P = S. With one vertex in S there is nothing to shrink — the savings appear when S is large.
