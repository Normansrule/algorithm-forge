Parallel Prefix Sums (Scan)

Running totals look hopelessly sequential: each one needs the one before. Yet with enough processors, Blelloch's scan computes all n of them in about 2 log₂ n parallel steps: O(log n) span with O(n) work, about twice the loop's additions. Scan is the workhorse behind graphics processing unit (GPU) sorting, stream compaction and much of parallel computing.

What's happening

Brent's theorem calculator

Work W = total operations; span S = number of parallel steps (the longest chain of dependent operations). Brent's theorem: with p processors a computation finishes in Tp ≤ W/p + S steps. Pick a problem size and a machine.

What scan is for

Both uses below run on the current input array. Each is "compute flags in parallel, exclusive-scan the flags, scatter in parallel": every step is a parallel step, so the whole thing has O(log n) span.

How to read this

The circuit
Each row is the array after one parallel step; time flows downward. A blue ⊕ circle is one processor combining the two values wired into it. Grey vertical wires are values that just carry over. The number of rows is the span; the number of ⊕ circles is the work. Rows not reached yet are drawn as empty outlines so you can see the shape (and the span) in advance.
Inclusive vs exclusive
An inclusive scan puts x₀ ⊕ … ⊕ xi in position i; an exclusive scan puts x₀ ⊕ … ⊕ xi−1 (identity in position 0). The sequential loop and Hillis–Steele are inclusive, Blelloch is exclusive. Convert with one parallel step: inclusive[i] = exclusive[i] ⊕ xi.
Why Blelloch is work-efficient
Hillis–Steele keeps almost every processor busy in every one of its log₂ n steps: n log₂ n − (n − 1) operations, far more than the n − 1 of the loop. Blelloch builds a balanced reduction tree (up-sweep, n − 1 operations) and walks back down it (down-sweep, n − 1 more): 2(n − 1) work in 2 log₂ n steps. With fewer processors than elements, total work is what decides the running time.
Any associative operator
Parallel scan only regroups the operations, so it needs (a ⊕ b) ⊕ c = a ⊕ (b ⊕ c), not commutativity. Try max and min: running maximum and running minimum come out of the same circuit. Blelloch pads n up to a power of two with the identity (0 for +, −∞ for max, +∞ for min).

Try this

  1. Example, three ways. Press Example (3, 1, 7, 0, 4, 1, 6, 3) and run each algorithm. Sequential: 7 steps, 7 additions, ending 3 4 11 11 15 16 22 25. Hillis–Steele: 3 steps but 7 + 6 + 4 = 17 additions. Blelloch: 6 steps of additions (+1 to set the root), 14 additions, giving the exclusive scan 0 3 4 11 11 15 16 22.
  2. Where's the total? In Blelloch's up-sweep, predict what the last cell holds before it is cleared: the total, 25. The down-sweep hands each left child "everything to the left of my block" and each right child that plus its sibling's subtotal.
  3. Scale n. Set n = 32 and press Random array. Hillis–Steele needs 5 steps but 129 additions; Blelloch 10 steps and 62 additions; the loop 31 steps and 31 additions.
  4. Brent. In the calculator, n = 1,048,576 and p = 1,024: Blelloch ≈ 2,088 steps, Hillis–Steele ≈ 19,476, the loop 1,048,575. Now press p = n: Hillis–Steele wins (≈ 39 vs ≈ 42) because span dominates. Real GPUs have far fewer cores than elements, so work-efficient scans win in practice.
  5. Compaction. In "What scan is for", keep x > 2 on the example: flags 1 0 1 0 1 0 1 1, exclusive scan 0 1 1 2 2 3 3 4 gives each kept element its output slot: 3 7 4 6 3.
  6. Radix split. Switch to the radix split and step b = 0, 1, 2 … Each split is stable, and repeating it for every bit sorts the array: the core of GPU radix sort.
