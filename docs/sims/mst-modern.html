Minimum spanning trees, parallel and randomized

A Minimum Spanning Tree (MST) is the cheapest set of edges that connects every vertex. Kruskal and Prim find it one edge at a time. Borůvka lets every component choose at once, which is why parallel and distributed codes use it, and Filter-Kruskal skips sorting the edges that cannot matter. All four run on the same graph and must agree.

Beyond O(m log n): randomized linear time, and Chazelle's bound

An explanation, not an implementation. n = number of vertices, m = number of edges.

Two facts do all the work. The cut property: the lightest edge leaving any set of vertices is in the MST (Borůvka's rule). The cycle property: the heaviest edge on any cycle is not. Given a forest F, call an edge F-heavy if it is heavier than every edge on the path in F between its ends; by the cycle property an F-heavy edge can never be in the MST, whatever F is.

Karger, Klein and Tarjan (1995) combine both:

  1. Shrink. Run two Borůvka rounds (like the ones animated above). The number of vertices drops by a factor of at least 4; the chosen edges are in the MST.
  2. Sample. Keep each remaining edge independently with probability ½ and recursively compute the minimum spanning forest F of that random half.
  3. Filter. Throw away every F-heavy edge of the whole graph. A linear-time MST verification algorithm (Komlós 1985; Dixon, Rauch and Tarjan 1992; King 1997) finds them all in O(m) time.
  4. Recurse on the edges that are left.

The key is a sampling lemma: if each edge is kept with probability p, the expected number of F-light edges is at most n/p, so here at most 2n edges survive the filter no matter how large m is. Expected time O(m); in the worst case O(min(n², m log n)).

Check the sampling lemma on this graph. Sample half the edges at random, build F, and count the F-light edges of the whole graph (F's own edges count as light).

Deterministic: Chazelle (2000). Without random bits, the best known time is O(m α(m, n)), where α is the inverse Ackermann function, at most 4 for any input that fits in our universe. It rests on the soft heap, a priority queue allowed to raise (corrupt) a controlled fraction of its keys, which makes it faster; the MST algorithm tolerates the errors and repairs them later.

Still open. Pettie and Ramachandran (2002) gave a deterministic algorithm that is provably optimal, yet nobody knows its running time: it lies between Ω(m) and O(m α(m, n)). Whether MST can be solved deterministically in linear time is an open problem.

In practice. Kruskal or Prim with a good heap are hard to beat on one core. Filter-Kruskal is a simple, fast choice when edges are many, and Borůvka-style rounds are the usual basis for parallel, distributed and GPU MST codes.

How to read this

  • Orange edges are in the tree. A blue edge is the one being looked at (in Borůvka: the edges chosen this round, with an arrow from the component that chose it). Red dashed means rejected because it would close a cycle; grey means discarded or filtered.
  • Vertex colours show the current components (the union-find sets) in Kruskal, Borůvka and Filter-Kruskal; uncoloured vertices are still alone. In Prim, green vertices are in the tree and yellow edges are in the heap.
  • In Borůvka's contraction frames each component is drawn as one big super-vertex (its size inside), joined by the lightest edge between each pair of components: the smaller graph the next round works on.
  • The strip under the graph is the edge array. Kruskal: sorted order (unvisited, kept, rejected). Filter-Kruskal: the current segment is boxed; blue = E≤ (not heavier than the purple pivot), light purple = E>, yellow = sorted in a base case, grey = filtered out without ever being sorted.

Try this

  1. Rounds halve. Run Borůvka on n = 60. Read the component counts in the narration: each round leaves at most half as many components as it started with, so there are never more than ⌈log₂ 60⌉ = 6 rounds (usually 3 or 4).
  2. Why ties need a rule. Load "All weights equal" and run Borůvka. Every edge of the triangle a–b–c weighs 1, so without a rule a could pick a–b, b pick b–c and c pick c–a: a cycle. With ties broken by edge index, a and b both pick a–b (#0) and c picks b–c (#1), and no cycle can form. Check that all four algorithms report the same edges in the table.
  3. Filter-Kruskal pays off on dense graphs. Set n = 60 and compare "sorted edges saved" for sparse and dense. On the dense graph most heavy edges are filtered out unsorted, and its comparisons drop well below Kruskal's.
  4. Threshold. In Filter-Kruskal, drag the threshold to 1 (pure quicksort-style recursion) and to 40 (almost plain Kruskal). Watch the edges-sorted counter.
  5. Prim's stale edges. With weights 1–9, run Prim and count the stale pops: edges that became useless while waiting in the heap.
