    Start with the door that suits you

    Everyone has a favorite first door. Walk in through yours, then try the others: the understanding that lasts is the one you have seen from several sides.

    👀

    Visual

    “I need to see it.”
    • Open the simulation before the lesson, and step slowly.
    • Type the exact example from the lesson into the sim and watch it match.
    • In the Arena or the Playground, press Visualize to watch your own code run.
    📖

    Story & analogy

    “Tell me what it's like.”
    • Read each Build Card's Story first: sorting cards, looking up a word, filling a backpack.
    • Read the sims' narration panel instead of watching the bars.
    • Explain the algorithm out loud in one sentence before writing anything.
    ✋

    Hands-on

    “Let me try it.”
    • Go straight to the Arena and attempt the problem cold.
    • Use Blocks mode when a blank page feels like too much.
    • Break things on purpose: change < to ≤ and predict what fails.
    ∑

    Math-first

    “Show me the proof.”
    • Start from the cheat sheet: sums, recurrences, the Master Theorem.
    • Jump to each card's Analyze it block, then read the code to see why the sum looks that way.
    • Try the Recurrence Lab.
    💻

    Code-first

    “Show me the code.”
    • Solve Arena problems in JavaScript or Python as well as pseudocode.
    • Read the tested library in src/python; it counts its own operations.
    • Keep the pseudocode reference open.
    Primary reference

    Anany Levitin, Introduction to the Design and Analysis of Algorithms, 3rd edition (Pearson, 2012). Chapters 1–12 follow its chapters and cite sections like “Levitin §4.2”. All explanations, examples and pseudocode here are written fresh for Algorithm Forge; get the book for the full treatment and exercises. The Atlas and Chapter 18 cite the original papers.
